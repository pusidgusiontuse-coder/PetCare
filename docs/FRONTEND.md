# React и TypeScript: первый этап

`app/index.html` теперь содержит только метаданные, `#root`, сообщение для отключённого JavaScript и точку входа Vite. Разметка разделов и диалогов вынесена в React-компоненты. Дизайн, URL с hash-навигацией и HTTP API сохранены.

## Структура

- `app/frontend/main.tsx` — подключение OCR, первый React render и загрузка старых обработчиков после появления DOM.
- `app/frontend/App.tsx` — каркас страницы.
- `app/frontend/components/` — боковая навигация, шапка, SVG-иконки и диалоги.
- `app/frontend/pages/` — отдельные компоненты питомцев, здоровья, питания, ухода, документов, профиля и сохранённого скрытого раздела друзей.
- `app/frontend/features/nutrition/` — журнал кормов, фильтр, оценки, сравнение кормов, типы и тесты. Данные приходят через store, локальные фильтры и выбор кормов управляются React.
- `app/frontend/lib/api.ts` — типизированный API-клиент: текущий JWT, обработка 401, ошибок FastAPI и загрузки файлов.
- `app/frontend/legacy/runtime.js` — оставшаяся логика синхронизации, форм, календаря, уведомлений и аккаунта. Это переходный JavaScript-модуль, не полностью типизированный TypeScript.
- `app/static/local-ocr.js` — локальное OCR; включается в сборку как модуль, движок и модели по-прежнему загружаются отдельно по запросу.
- `vite.config.ts`, `tsconfig.json`, `eslint.config.js` — сборка, строгая проверка нового TS/TSX и правила React Hooks.

Компоненты каркаса монтируются один раз. Старые обработчики заполняют оставленные пустыми контейнеры данных и меняют классы навигации. Они не должны менять узлы внутри `NutritionTools`: всем этим поддеревом управляет React. Store копирует изменяемые legacy-данные в стабильный snapshot; переключение питомца сбрасывает фильтры через `resetNutritionFilters()`, а не через `.value` DOM-элемента.

Следующие разделы можно переносить по тому же принципу: типы → компонент → явный мост данных → удаление соответствующего DOM-renderer. Пока React не управляет всей бизнес-логикой приложения; `checkJs: false` относится к оставленному JavaScript, а новый TypeScript проверяется с `strict: true`. Старый отдельный `enhancements.js` удалён, обработчики аккаунта включены в единый модуль совместимости без зависимости от глобальной области видимости.

## Запуск

Нужны Node.js 22.12+ и Python-окружение с настроенным PostgreSQL. Версии пакетов и транзитивные зависимости фиксируются `package-lock.json`.

```sh
npm ci
npm run lint
npm test
npm run build
source .venv/bin/activate
python -m alembic upgrade head
python -m uvicorn main:app --app-dir app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000/`. Сборка находится в `app/static/frontend/`: FastAPI отдаёт её HTML на `/`, а JS/CSS с хешами — через `/static/frontend/assets/`. Исходные `.tsx` браузеру не отдаются. Без сборки `/` возвращает 503 с командой сборки; API продолжает работать.

Для разработки запустите API на порту 8000, а во втором терминале:

```sh
npm run dev
```

Vite доступен по `http://127.0.0.1:5173/static/frontend/`. API, PWA и OCR-запросы проксируются в FastAPI. Порт backend задаётся в `vite.config.ts`. Веб-приложение запускайте через HTTP, не открытием HTML как локального файла.

## Хостинг и CI

На Python-хостинге Node.js не обязателен: выполните `npm ci && npm run build` локально или в CI и загрузите **весь** `app/static/frontend/` вместе с обновлёнными исходниками. Одного исходного `index.html` недостаточно. Не запускайте сервер между удалением старых и загрузкой новых assets; держите согласованный комплект HTML и JS/CSS.

`setup_hosting.py` проверяет наличие собранного HTML до изменения окружения. GitHub Actions выполняет установку, lint, TypeScript, unit-тесты и production build до серверных/браузерных тестов. Артефакт `frontend-build` содержит готовую сборку, хранится 7 дней. GitLab строит frontend отдельным заданием и передаёт артефакт тестам. Сгенерированные assets и `node_modules` не коммитятся.

`npm run lint` проверяет правила хуков нового React/TS кода; `npm test` — API-клиент, группировку кормов, выбор разных кормов, стабильность snapshot и отписку от store. Существующие browser tests проверяют production build на компьютере и телефоне, включая сохранение корма и сброс фильтра при смене питомца. Для них используется отдельная PostgreSQL-база.

Для старых browser fixtures есть opt-in флаг `window.__PETCARE_TEST__`, устанавливаемый до загрузки страницы. Только при нём runtime публикует совместимый тестовый доступ к состоянию и действиям. В обычном запуске этого доступа нет. Флаг не меняет серверные права и не заменяет авторизацию.

В ESLint parser временно зафиксирован исправленный `minimatch` через scoped override; это устраняет advisory GHSA-g3hv-75wg-m249 в транзитивной dev-зависимости. После обновления parser override можно пересмотреть через `npm audit`, lint и тесты.

Подход к постепенному переходу: [React в существующем проекте](https://react.dev/learn/add-react-to-an-existing-project), [Vite и backend](https://vite.dev/guide/backend-integration).
